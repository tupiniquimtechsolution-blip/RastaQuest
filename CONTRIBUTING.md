# Contributing

RastaQuest is currently in pre-production and repository normalization.

## Before changing code or design

1. Read `AGENTS.md`.
2. Read `docs/status/CURRENT_STATE.md`.
3. Check the relevant PE wave in `docs/roadmap/PE_EXECUTION_WAVES.md`.
4. Confirm whether the source material is current or legacy.
5. Reference an issue for material changes.

## Branch naming

Use `feat/<scope>`, `fix/<scope>`, `chore/<scope>`, `docs/<scope>` or `test/<scope>`.

## Pull requests

State objective, scope, files/systems changed, checks executed, architecture impact, risks, and rollback notes. Gameplay/UI changes should include screenshots or video when possible.

## Architecture

Create or update an ADR for changes to engine/platform strategy, module boundaries, data formats, save compatibility, networking, security boundaries or build/release architecture.

## Legacy material

Do not rewrite legacy sources to make them agree with current plans. Preserve the original and document the superseding decision separately.
